# Онлайн-статус и набор текста

## Подключение

В Supabase → SQL Editor выполните `supabase/social_presence.sql`, затем
`supabase/last_seen.sql`. Если первый файл уже применён, достаточно второго.
Миграция каналов
повторяемая: она создаёт функцию проверки доступа и четыре RLS-политики
для приватных каналов в `realtime.messages`. Рабочие таблицы приложения
не изменяются. Глобально отключать публичные каналы Realtime не требуется.
После применения перезагрузите Melo в открытых браузерах.

SQL подготовлен локально; его применение в рабочем Supabase не выполнялось агентом.

## Поведение

- Статус друга виден на странице друзей, возле аватара в списке переписок
  и под именем в открытом диалоге.
- «В сети» означает, что у пользователя есть хотя бы одно подключение Melo.
  Несколько вкладок учитываются; закрытие одной не делает пользователя офлайн.
  Фоновая вкладка остаётся онлайн. После обрыва связи статус меняется,
  когда сервер обнаруживает отключение последней сессии.
- Вместо «Не в сети» показано последнее подтверждённое посещение:
  «Был(а) в сети сегодня в 14:32», «вчера…» или дата и время.
  Пока записи ещё нет, выводится «Время посещения пока неизвестно».
- В открытом диалоге статус временно заменяется на «печатает…».
  Сигнал отправляется при вводе с ограничением частоты раз в две секунды.
  Он прекращается после паузы 3 секунды, очистки поля, отправки сообщения,
  потери фокуса, скрытия вкладки или выхода из диалога.
- Если завершающий сигнал потерян, надпись исчезает через четыре секунды
  после последнего сигнала. Текст черновика не передаётся.

Онлайн-статус доступен только принятым друзьям. Публиковать присутствие можно
только в собственном канале. Сигналы набора доступны только участникам
принятой дружбы в канале их пары. Ограничительные политики защищают эти
префиксы даже при наличии старых широких разрешений Realtime.
Supabase кеширует разрешения на время подключения; отзыв дружбы не является
гарантией мгновенного отзыва уже открытой сессии. Приложение сверяет список
друзей при событиях, возвращении во вкладку и раз в минуту.

Демонстрационные друзья на главной странице остаются демонстрационными.
`user_activity` хранит только последнюю метку времени. RPC `touch_user_activity`
обновляет только собственную запись по серверным часам, без параметров;
прямые клиентские записи запрещены. Читать метки могут пользователь и принятые
друзья. Отметка обновляется при входе, подключении Presence, каждые 30 секунд,
возвращении во вкладку и восстановлении сети, пока вкладка видима и браузер
подключён к сети. Повторные события в течение 25 секунд после успешной записи
не вызывают лишних запросов. Присутствие в фоновой вкладке по-прежнему
поддерживается через Realtime; метка посещения отражает последнее успешное
обновление в видимой вкладке, а не точную секунду отключения.

При скрытии и закрытии вкладки новый RPC не отправляется: браузер может
прервать такой запрос. При отключении компонента незавершённый запрос
отменяется. На запрос отведено 10 секунд; после сетевого сбоя обновление
повторяется при восстановлении связи или следующей активности.
Некритичные сбои активности записываются через `console.warn`, с кодом и
текстом ошибки, один раз до восстановления или изменения ошибки. Они не
вызывают красное окно Next.js, как прежний `console.error` с объектом `{}`.

RPC реализована с фиксированным `search_path` и доступом только для
авторизованных пользователей, согласно [документации Supabase](https://supabase.com/docs/guides/database/functions#security-definer-vs-invoker).

## Файлы и проверки

- `src/context/SocialPresenceContext.tsx` — присутствие пользователя и подписки на друзей.
- `src/hooks/useTypingIndicator.ts` — приватный канал диалога, таймеры и остановка набора.
- `src/lib/socialPresence.ts` — имена каналов, состояния и проверка сигналов.
- `tests/social-presence.test.mjs` — парные каналы, несколько сессий,
  приём и отправка сигналов, таймеры, отключение и очистка подписки.

Запуск: `node --test tests/social-presence.test.mjs`.

Права каналов отдельно проверены в изолированном PostgreSQL (PGlite):
повторное применение миграции, присутствие нескольких типов пользователей,
доступ обоих участников к набору, запрет чужих и ожидающих заявок,
защита от старых широких политик и сохранение посторонних каналов.
Это локальная проверка SQL; подключение к рабочему Realtime она не заменяет.
Повторный запуск: `node tests/check-social-presence-db.mjs` после установки
временного PGlite по команде из комментария этого файла.

`node tests/check-last-seen-db.mjs` проверяет серверное время, запрет прямых
записей и подмены чужой активности, чтение только для принятых друзей,
отзыв доступа после удаления дружбы и повторное применение миграции.
Для этой проверки: `npm install --prefix .music-import/db-check --no-save --package-lock=false --ignore-scripts @electric-sql/pglite`.

`node --test tests/user-activity.test.mjs` проверяет пропуск недоступного
соединения, ограничение частоты, отсутствие параллельных запросов, повтор
после сбоя/тайм-аута и отмену запроса при отключении компонента.

Диагностика 14 октября 2026: в рабочем Supabase подтверждены наличие функции
и таблицы, необходимые права и успешное выполнение RPC с ролью authenticated
в транзакции с откатом. В доступном журнале API за последний час найденные
вызовы `touch_user_activity` имеют статус 2xx, без 4xx/5xx. Исходная ошибка
со скриншота не воспроизвелась; её точный сетевой ответ не сохранился в
доступном журнале браузера. Исправлены выявленные проблемы жизненного цикла
запроса и обработки временного обрыва связи; схема базы не изменялась.
