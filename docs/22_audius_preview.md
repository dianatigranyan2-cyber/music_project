# Добавление музыки из Audius

В `/admin/music` у администратора каталога есть кнопка
«Добавить из Audius». Можно искать по названию/аккаунту или вставить HTTPS-ссылку
на отдельную песню `audius.co`. Кнопка «Проверить» повторно получает метаданные
и сведения о доступе. Для открытых треков появляется проверочное прослушивание
с перемоткой. Основной плеер приглушается на время прослушивания.

После проверки уточните название, настоящего исполнителя, альбом и жанр,
затем нажмите «Добавить в Melo». У неподтверждённого аккаунта исполнителя нужно
заполнить самостоятельно. Источник, аккаунт и условия сохраняются автоматически;
загружать MP3 и вручную писать лицензию не требуется.

В Supabase сохраняются сведения и идентификатор, аудио остаётся в Audius.
Запись получает UUID Melo и работает в поиске, страницах исполнителей, избранном,
плейлистах и основном плеере. Повторный импорт не создаёт копию, не заменяет
исправленные данные и не публикует скрытый трек.

Снимите «Показывать трек в каталоге», чтобы сохранить черновик. Через «Изменить»
можно исправить сведения, опубликовать или скрыть песню. Публикация повторно
проверяет Audius, скрытие работает даже при сбое провайдера. Для историй эти
песни пока недоступны. Собственные файлы добавляются через «Загрузить файл».

## База и развёртывание

После существующих схем каталога и администрирования примените
`supabase/audius_catalog.sql` в SQL Editor перед развёртыванием кода. Миграция
повторяема и атомарна: добавляет источник и метаданные, отдельную функцию импорта
с проверкой администратора и запрет Audius в историях. Прежние файлы, плейлисты
и требования к собственным файлам сохраняются.

До обновления размещённого приложения сохраняйте записи Audius скрытыми:
старая версия плеера ещё не знает этот источник. После развёртывания можно
опубликовать их через «Изменить».

## Подключение

Публичные запросы работают без токена в пределах ограничений Audius. При наличии
токена приложения добавьте **только на сервере** в `.env.local`:

```dotenv
AUDIUS_BEARER_TOKEN=значение_из_личного_кабинета_Audius
```

Не используйте префикс `NEXT_PUBLIC_`, не коммитьте значение и не вставляйте его
в клиентские URL. После изменения переменных перезапустите локальный сервер.
Для размещённой версии задайте эту переменную в окружении Vercel и выполните
новое развёртывание. Передавать токен в чат не нужно.

Поиск, проверка, импорт и редактирование защищены серверной проверкой `is_music_admin`.
REST-запросы к Audius передают токен только серверу `api.audius.co`. Предпрослушивание
перенаправляет браузер на публичный поток Audius без токена; доступны только
открытые треки. MP3 не копируются в Supabase, потоки не проксируются через Vercel.

Основной плеер использует `/api/music/audius/<UUID Melo>/stream`: сервер проверяет
публикацию через RLS и свежий доступ Audius, затем перенаправляет на публичный поток.
Пауза, перемотка и фон используют аудиоплеер браузера; работа при блокировке на
конкретном телефоне зависит также от браузера и системы.

## Что означает проверка

- «Доступно для прослушивания» — Audius подтвердил доступность, возможность
  стриминга и открытый доступ, а ограничения не обнаружены.
- «Нужна дополнительная проверка» — часть данных отсутствует. Если технический
  доступ подтверждён, а не указана только лицензия, доступно прослушивание.
- «Прослушивание недоступно» — удалённый, скрытый или закрытый трек, условия
  покупки/подписки, ограничения для приложений либо отказ в доступе.

Это проверка текущего ответа API, не подтверждение авторских прав и не обещание
доступности для всех будущих слушателей/регионов. Лицензия отображается как
передана Audius. `All rights reserved` не подменяется Creative Commons: использование
через API отдельно регулируется условиями Audius/OML и настройками автора.
В каталоге хранится отдельная отметка `Audius-OML`, исходная лицензия сохраняется
в метаданных и указании авторства. Импорт разрешён только при статусе «Доступно
для прослушивания». При изменении доступа повторное воспроизведение блокируется.
Аккаунт загрузившего явно обозначен как аккаунт Audius, а не автоматически
подтверждённый исполнитель. Проверка не обходит закрытый/платный доступ.

Документация: https://docs.audius.co/api/
Условия: https://blog.audius.co/posts/audius-terms-of-service-update

## Проверки

`node --test tests/*.test.mjs`: API, валидация, права, отзыв доступа, каталог и очередь.
`node tests/check-audius-catalog-db.mjs`: изолированная база PGlite, повторная миграция,
прежние файлы, дубликаты, публикация, избранное, плейлисты и запрет в историях.
Для последней проверки нужен PGlite в `.music-import/db-check/node_modules`;
она не обращается к рабочей Supabase.
