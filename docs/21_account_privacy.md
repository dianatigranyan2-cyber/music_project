# Приватность аккаунта

В своём профиле кнопка «Настройки» открывает `/settings`. Выход из аккаунта находится внизу этой страницы, в верхней панели его нет.

В начале настроек можно выбрать публичный или закрытый аккаунт. Выбор сохраняется сразу; до подтверждения сервером отображается прежнее значение. При ошибке показано сообщение для повторной попытки. Существующие аккаунты остаются публичными, пока владелец сам не изменит настройку.

- Имя, никнейм и аватар доступны всем и позволяют найти человека и отправить запрос в друзья.
- У публичного аккаунта описание, число друзей, любимые песни, их жанры и выбранные для профиля плейлисты доступны всем.
- У закрытого аккаунта эти сведения доступны владельцу и принятым друзьям. Непринятые, отклонённые и удалённые связи доступа не дают.
- Только плейлисты с `show_on_profile` отображаются посетителям, включая друзей. Доступ по отдельно включённой ссылке `is_shared` сохраняется независимо от приватности аккаунта; это поясняется в настройках.

## Сервер

Миграция `supabase/account_privacy.sql` применяется **после** `profile_music.sql`; в текущем Supabase она применена. Повторное выполнение сохраняет выбранные значения.

Колонка `profiles.is_private` хранит настройку. Прямой SELECT профилей разрешён только для публичных полей идентификации. Доступ к `bio` через общий SELECT закрыт, чтобы нельзя было обойти ограничение профиля отдельным запросом.

- `account_profile()` возвращает данные только текущего владельца.
- `update_account_profile(jsonb)` принимает только разрешённые поля и изменяет только профиль текущей сессии, возвращая подтверждённые данные одним запросом. Ограничиваются типы и длины значений.
- `can_view_profile_details(uuid)` проверяет публичность, владельца или принятую дружбу.
- `profile_directory()` возвращает описание в списках и поиске только при наличии доступа.
- `music_public_profile(text)` выдаёт скрытому посетителю только идентификацию, `canViewDetails=false`, пустую музыку и `friendCount=null`.
- Обложки плейлистов защищены той же проверкой; ранее созданные подписанные ссылки действуют не более 60 секунд. Отдельно расшаренные ссылки на плейлисты работают независимо.

Публичный профиль загружается без кеширования, обновляется при фокусе/возврате на вкладку и раз в 30 секунд на видимой странице. При смене аккаунта результат предыдущего посетителя сразу исключается из отображения.

## Проверка

`tests/check-profile-music-db.mjs` проверяет роли гостя, владельца, принятого друга, пользователя с непринятым запросом и бывшего друга, защиту прямого чтения описания, чужих изменений, обложек и независимых ссылок на плейлисты. Также проверены повторная миграция и публичное открытие профиля обратно.

Unit-тесты проверяют скрытый профиль без деталей и начальные/загружаемые значения переключателя. В браузере проверены загрузка настоящей настройки, вход в настройки из профиля, списки друзей, поиск людей и отсутствие кнопки выхода в шапке. Приватность живых аккаунтов при проверке не переключалась.
