# Музыкальные функции Melo — 15 октября 2026

## Где найти

- **Плейлисты → Недавно прослушано**: последние включённые песни. История появляется после реального начала звучания, а не при выборе песни или восстановлении на паузе. Повторное прослушивание поднимает песню в начало. Показываются 100 последних разных песен; история хранится в аккаунте.
- **Плейлисты → Исполнители / Альбомы**: сохранённые страницы. Кнопка сохранения находится на странице исполнителя или альбома; повторное нажатие убирает запись из сохранённых.
- **Личный плейлист**: автоматическая обложка из первых песен или загрузка своей PNG/JPEG/WebP до 5 МБ. Кнопка «Автоматическая обложка» возвращает коллаж. Если временная ссылка изображения истекла, показывается коллаж; обновление личной библиотеки получает новую ссылку.
- **Повтор в плеере**: нажатия переключают «выключен → вся очередь → один трек». При повторе очереди её последняя песня автоматически сменяется первой; при повторе песни используется нативный audio.loop. Режим запоминается после обновления, старые сохранения плеера совместимы.
- **Верхний поиск**: подсказки исполнителей, альбомов и песен; стрелки выбирают вариант, Enter открывает/воспроизводит его, Escape закрывает подсказки. Enter без выбора показывает все результаты. «е» и «ё» считаются одинаковыми. На странице друзей поле продолжает искать друзей и не перенаправляет Enter в музыкальный каталог.
- **Главная → Обзор музыки → Подборки по настроению**: лирическая музыка, работа, спокойный вечер, прогулка. На главной также находятся исполнители, альбомы и полный каталог. Подборки отбирают доступные песни по указанным жанрам и автоматически включают подходящие новые записи. Старый адрес `/explore` перенаправляет к музыкальному обзору на главной.
- **Раскрытый нижний плеер → Добавить в плейлист**: выбор существующего плейлиста; уже добавленные песни отмечены галочкой. Ссылка «Создать плейлист» закрывает плеер и открывает личную библиотеку.
- **Авторы и лицензии**: сведения обо всех песнях перенесены на `/music/credits`; ссылка находится под каталогом. В плеере «Информация о треке» открывает сведения о текущей песне. Повторяющиеся блоки под каждой песней и рекламный баннер совместного прослушивания на главной убраны.
- **Личный плейлист → Включить доступ по ссылке**: владелец явно открывает подборку для людей со ссылкой. Её можно скопировать или открыть. «Закрыть доступ» отзывает ссылку; повторное включение создаёт новую. Плейлисты по умолчанию закрыты. Отправка друзьям автоматически не выполняется.

Ссылка ведёт на текущий адрес сайта. На localhost её можно открыть только там, где доступен этот локальный сервер. Для друзей на других компьютерах понадобится опубликованный сайт с доступным адресом; сама функция ссылок уже работает.

## Подключение

После `music_library.sql`, `music_library_licenses.sql` и `personal_music.sql` выполнить **`supabase/music_features.sql`**. В текущем Supabase `music_project_melo` она уже выполнена.

Новые таблицы: `music_history`, `music_saved_artists`, `music_saved_albums`. RLS разрешает чтение и изменение только собственных данных. RPC `music_record_listen` использует auth.uid() и серверное время, принимает только опубликованные песни и не принимает пользовательскую дату или ID владельца. История не отправляется в общую аналитику.

У `music_playlists` добавлены `cover_path`, `is_shared`, `share_token`. Прямого анонимного доступа к личным таблицам нет. RPC `music_shared_playlist` выдаёт только запрошенную включённую подборку с опубликованными песнями; личная история, избранное, email и другие данные профиля в неё не входят. При отключении старый токен становится недействителен.

Обложки находятся в **приватном** bucket `music-playlist-covers`. Загружать можно только в собственную папку, приложение проверяет размер, MIME и сигнатуру изображения; SVG не принимается. Ограничение таблицы не позволяет прикрепить обложку из папки другого аккаунта. Даже при старых широких Storage-политиках ограничительные правила сохраняют эту защиту. Для владельца создаются подписанные URL на час, для открытой подборки — на минуту. Отключение ссылки закрывает новые запросы; уже выданная ссылка изображения может действовать до конца этой минуты. Скачанное ранее изображение отозвать невозможно.

Ключ service-role в приложении не используется. Публичный каталог загружается одним общим провайдером; ввод каждого символа не вызывает новый запрос к Supabase.

## Проверки

- `node --test tests/*.test.mjs`: 40 тестов, включая переходы повторов, границы очереди, порядок истории при запоздавших ответах, подсказки, «е»/«ё», жанры и проверку файлов обложек.
- `node tests/check-music-features-db.mjs`: отдельный временный PostgreSQL (PGlite), повторная миграция, изоляция аккаунтов, запрет сохранения неопубликованных записей и подмены времени, ссылки и отзыв, приватные обложки, защита от старых широких политик.
- `node scripts/check-music-remote.mjs`: только чтение, проверка 38 записей и аудиофайлов в настоящем Supabase.
- В браузере проверены подсказки клавиатурой, сохранение исполнителя/альбома, история, режимы повтора, настоящий переход с последней песни на первую, загрузка и отображение своей обложки, сохранение после обновления.
- Открытие тестовой подборки и её обложки без входа дополнительно проверено HTTP-запросом без cookies. После отключения ссылки тот же запрос вернул 404.

В аккаунте оставлена приватная подборка **«Новая музыка»**: «Возьмёмся за руки», «Ветер в метро», «Свет», с тестовой обложкой. Доступ по ссылке после проверки отключён; прежние личные подборки не публиковались.

Нативный audio продолжал воспроизведение при скрытой панели браузера на компьютере. Однако среда сообщала document.visibilityState='visible', поэтому это не полная проверка скрытой вкладки. Физическая блокировка телефона пока не проверена — доступен только компьютер. Средство изменения viewport также оставило фактическую ширину 1280 вместо заданных 390; проверка мобильной раскладки не засчитывается. При появлении телефона нужно проверить Safari/Chrome, блокировку экрана, системные кнопки и переход на следующую песню.
