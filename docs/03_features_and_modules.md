
# 03. Функциональные модули приложения

В этом документе подробно описаны все ключевые функциональные модули Melo, алгоритмы их работы, используемые компоненты и особенности реализации.

---

## 1. Авторизация и профили пользователей

Модуль реализован в `src/context/AuthContext.tsx`, `src/app/login/page.tsx`, `src/app/register/page.tsx`, `src/app/settings/page.tsx` и `src/app/profile/[username]/page.tsx`.

### 1.1. Регистрация (`signUp`)
1. Пользователь вводит: Email, Пароль, Имя пользователя (username) и Отображаемое имя (display_name).
2. **Валидация Username на клиенте**:
   - Длина: не менее 3 символов.
   - Символы: только латинские буквы, цифры и символ подчеркивания (`^[a-zA-Z0-9_]+$`).
3. **Проверка уникальности в БД**:
   - Перед созданием аккаунта выполняется запрос:
     ```ts
     supabase.from('profiles').select('id').eq('username', cleanUsername).maybeSingle();
     ```
   - Если запись найдена, пользователю возвращается ошибка: *«Это имя пользователя уже занято»*.
4. **Создание учетной записи**:
   - Вызывается `supabase.auth.signUp({ email, password, options: { data: { username, display_name } } })`.
   - В таблицу `profiles` вставляется запись с `id = user.id`. Если триггер в базе уже создал запись, выполняется `.upsert()`.

### 1.2. Вход и выход (`signIn`, `signOut`)
- Вход: `supabase.auth.signInWithPassword({ email, password })`. При успехе `AuthContext` автоматически подтягивает профиль из `profiles`.
- Сессия: токен сохраняется в локальном хранилище браузера (LocalStorage) и синхронизируется через Cookies для SSR.
- Выход: `supabase.auth.signOut()`, очищает состояние пользователя и профиля в памяти React.

### 1.3. Редактирование профиля и загрузка аватара
- Реализовано в `src/app/settings/page.tsx`.
- **Загрузка аватара (`uploadAvatar`)**:
  1. Проверка типа файла: разрешены только `image/jpeg`, `image/png`, `image/webp`.
  2. Проверка размера: максимум 5 МБ (`file.size <= 5 * 1024 * 1024`).
  3. Загрузка в бакет Storage `avatars`: путь `${user.id}/avatar-${Date.now()}.${ext}`.
  4. Получение публичной ссылки: `supabase.storage.from('avatars').getPublicUrl(path)`.
  5. Запись ссылки в поле `avatar_url` таблицы `profiles`.

## 2. Модуль «Друзья» (Friends)

Реализован в `src/app/friends/page.tsx` и карточке `src/components/FriendCard/FriendCard.tsx`.

### 2.1. Вкладки управления друзьями
1. **«Все друзья»**:
   - Запрашивает из `friend_requests` записи со статусом `'accepted'`, где текущий пользователь является `sender_id` либо `receiver_id`.
   - Загружает данные противоположных профилей (`profiles`).
2. **«Входящие заявки»**:
   - Записи `friend_requests`, где `receiver_id = currentUser.id` и `status = 'pending'`.
   - Доступны действия: **Принять** (`status = 'accepted'`) и **Отклонить** (`delete`).
3. **«Исходящие заявки»**:
   - Записи `friend_requests`, где `sender_id = currentUser.id` и `status = 'pending'`.
   - Доступно действие: **Отменить заявку** (`delete`).
4. **«Поиск пользователей»**:
   - Полнотекстовый поиск по колонкам `username` и `display_name` через оператор `.or(\`username.ilike.%${query}%,display_name.ilike.%${query}%\`)`.
   - Исключает текущего пользователя из выдачи.

### 2.2. Карточка друга (`FriendCard`) и статус прослушивания
- Карточка отображает аватар, имя, никнейм, онлайн-индикатор и статусное сообщение.
- **Особенность архитектуры**:
  - Связи друзей и заявки работают с **реальной базой Supabase**.
  - Однако онлайн-статус и текущий воспроизводимый трек друга на главной странице формируются на основе **демо-данных (`mockData.ts`)**, так как Supabase Realtime Presence для вещания текущего трека в текущей версии еще не интегрирован в глобальный стейт.

## 3. Личные сообщения (Messages)

Реализован в `src/app/messages/page.tsx`. Это один из самых сложных компонентов системы (более 2700 строк кода).

### 3.1. Структура интерфейса
- **Двухпанельный макет**:
  - Слева: список диалогов с друзьями, фильтрация через строку поиска, превью последнего сообщения и время.
  - Справа: активное окно переписки, история сообщений, форма ввода текста, плашка прикрепленной истории.
- **Мобильная адаптивность**:
  - На экранах телефонов список чатов и активный чат переключаются как отдельные экраны (`selectedChatId ? styles.chatOpen : ''`).
  - При открытии чата скрываются нижнее меню навигации и компактный плеер, чтобы клавиатура и поле ввода не перекрывались.

### 3.2. Realtime синхронизация сообщений
Компонент создает три раздельных канала Supabase Realtime:
1. `messages-insert-${user.id}`: ловит события `INSERT`. При получении нового сообщения от текущего собеседника мгновенно добавляет его в чат и, если чат открыт, отправляет `read_at = now()`.
2. `messages-update-${user.id}`: ловит события `UPDATE`. Обновляет текст (при редактировании) и проставляет статус прочтения (синяя двойная галочка).
3. `messages-delete-${user.id}`: ловит события `DELETE`. Мгновенно удаляет сообщение из стейта без перезагрузки страницы.

### 3.3. Редактирование и удаление сообщений
- **Редактирование**:
  - Вызывается через контекстное меню сообщения («Редактировать»).
  - Отправляет вызов RPC: `supabase.rpc('edit_own_message', { p_message_id, p_new_content })`.
  - После редактирования отображается пометка *(ред.)*.
- **Удаление**:
  - Вызывается через меню («Удалить»).
  - Выполняет запрос `supabase.from('messages').delete().eq('id', messageId)`.

### 3.4. Ответы на истории (Story Replies & Previews)
- Если сообщение создано как реакция или ответ на историю (`is_story_reply: true, story_id: '...'`):
  1. Функция `fetchStorySnippets` загружает данные истории из таблицы `stories`.
  2. Запрашивает временную подписанную ссылку: `supabase.storage.from('stories').createSignedUrl(story.media_path, 300)`.
  3. Если история найдена — в теле сообщения отображается миниатюра медиа с возможностью клика и перехода в `/stories/[id]`.
  4. **Если история удалена или просрочена** (`storySnippet === null`):
     - Рендерится специальный бейдж: `📷 История недоступна`.
  5. Для надежности реализованы повторные попытки (retry) через 2 и 5 секунд при сбоях сети.

## 4. Модуль историй (Stories)

Реализован в `src/components/Stories/StoriesBar.tsx` и `src/app/stories/[id]/page.tsx`.

### 4.1. Публикация истории (`StoriesBar`)
1. В горизонтальной ленте историй первой карточкой отображается аватар текущего пользователя с кнопкой `+`.
2. При клике активируется скрытый `<input type="file">`.
3. Поддерживаемые форматы: `image/jpeg`, `image/png`, `image/webp`, `video/mp4`, `video/webm`.
4. Загрузка файла в приватный бакет Supabase Storage `stories`:
   - Путь: `${user.id}/${Date.now()}-${file.name}`.
5. Создание записи в таблице `stories`:
   - `media_path`: путь в бакете;
   - `media_type`: `'video'` или `'image'`;
   - `expires_at`: выставляется на 24 часа вперед.
6. В случае ошибки записи в БД файл немедленно удаляется из Storage во избежание «мусорных» файлов.

### 4.2. Полноэкранный плеер историй (`/stories/[id]`)
- **Воспроизведение и таймеры**:
  - Для фото: автоматический таймер длительностью **5 секунд**.
  - Для видео: таймер синхронизирован с реальной длительностью видео (`video.duration`).
  - Полоса прогресса плавно анимируется сверху экрана.
  - По завершении времени происходит автопереход к следующей истории либо закрытие плеера.
- **Пауза по зажатию (Hold to pause)**:
  - События `onMouseDown`, `onTouchStart`: таймер встает на паузу, видео останавливается, полоска замирает.
  - События `onMouseUp`, `onTouchEnd`: воспроизведение возобновляется.
- **Реакции и просмотры**:
  - При открытии истории создается запись в таблице `story_views`.
  - Внизу доступны кнопки быстрых реакций (🔥, ❤️, 😂, 👏, 😮, 😢), записываемые в `story_reactions`.
- **Удаление истории**:
  - Доступно только автору через кнопку «Удалить».
  - Алгоритм: сначала удаляется файл из бакета Storage через `supabase.storage.from('stories').remove([story.media_path])`, затем удаляется строка из таблицы `stories`.

## 5. Музыкальный плеер, комнаты и плейлисты

### 5.1. Музыкальный плеер (`Player.tsx`)
- Глобальный плеер, расположенный в нижней части окна в `AppShell`.
- Музыка не прерывается при переходе между любыми страницами сайта.
- **Функционал**:
  - Старт / Пауза (`isPlaying`).
  - Перемотка трека по таймлайну (Seek Bar).
  - Регулировка громкости и Mute.
  - Случайный порядок (Shuffle) и Повтор (Repeat).
  - Добавление в избранное (лайк).
  - Полноэкранный режим плеера на мобильных устройствах (`isExpandedMobile`).
- **Текущая природа данных**:
  - Плеер использует демонстрационный список `DEMO_TRACKS` из `mockData.ts`.
  - Симуляция воспроизведения происходит через JS-таймер `setInterval` в связке со стейтом секунды трека.

### 5.2. Совместные комнаты (`/room/[id]`)
- Демонстрационная страница совместного прослушивания («Синтвейв & Ночной Чилл 🎧»).
- Отображает список участников (хост и слушатели), очередь треков и live-чат.
- **Текущая природа данных**:
  - Чат комнаты работает на локальном стейте React (`useState`), сообщения не сохраняются в базу данных Supabase. Это интерактивный прототип интерфейса (UI Mockup).

### 5.3. Плейлисты (`/playlists`)
- Разделы: «Мои», «Совместные», «Любимые треки».
- Поддерживает создание нового плейлиста через модальное окно.
- **Текущая природа данных**:
  - Плейлисты хранятся в локальном стейте `myPlaylists` страницы. Для постоянного сохранения требуется будущая интеграция с таблицей `playlists` в Supabase.
