# Реальные данные профиля — 16 октября 2026

На `/profile` показываются данные вошедшего аккаунта. На `/profile/[username]` тот же вид профиля доступен другим людям, в том числе без входа. Владелец видит кнопки редактирования и все свои плейлисты; посетители — выбранные для профиля плейлисты и любимые песни. Демонстрационные имя, биография, жанры, статистика и песни не используются.

- Имя, ник, описание и аватар берутся из `profiles` текущего пользователя. Профиль другого аккаунта не используется даже при запоздавшем обновлении. Для отсутствующего аватара применяется `/default-avatar.png`, для отсутствующей биографии — соответствующая подпись.
- Число друзей — уникальные вторые участники принятых `friend_requests`. Входящие и исходящие заявки учитываются одинаково; ожидающие заявки в число друзей не входят. Счётчик загружается при открытии страницы, обновляется по Realtime и при возврате фокуса. Запоздавшие ответы и результаты предыдущего аккаунта не подменяют текущие данные.
- Число плейлистов и любимых треков берётся из личной музыкальной библиотеки пользователя. Состояния загрузки, ошибки и пустой библиотеки различаются: неизвестное количество не заменяется нулём.
- «Жанры любимых треков» — уникальные жанры доступных песен из избранного. Это описание коллекции, а не вручную указанные предпочтения пользователя.
- Вместо истории показываются «Плейлисты» и «Любимые песни». Карточки плейлистов идут горизонтальным рядом; нажатие открывает песни на этой же странице. Можно включить весь плейлист или отдельную песню. История остаётся в личной музыкальной библиотеке.
- У каждого плейлиста владельца есть «Показывать в профиле». Настройка сохраняется в `music_playlists.show_on_profile` и по умолчанию выключена. Она не меняет `is_shared`, не включает и не отключает существующие ссылки. Посетитель видит только выбранные плейлисты; счётчик плейлистов у него соответствует доступным карточкам.
- Фактическое время прослушивания пока не собирается и не выводится в профиле.

Публичные данные выдаёт `/api/profiles/[username]` через RPC `music_public_profile(text)`. Миграция **`supabase/profile_music.sql`** применяется после `music_features.sql`, а **`supabase/account_privacy.sql` — после неё**; обе выполнены в текущем Supabase. RPC возвращает поля профиля, число принятых уникальных друзей, опубликованные любимые песни и выбранные для профиля плейлисты с опубликованными треками. Для закрытого аккаунта эти подробности доступны только владельцу и принятым друзьям; остальные получают имя, никнейм и аватар с отметкой закрытого аккаунта. Email, история, токены доступа по ссылке, сохранённые исполнители и альбомы не выдаются. Прямой доступ к личным таблицам ограничен RLS; описание профиля читается через проверяемые RPC. Обложки выбранных плейлистов читаются через короткие подписанные ссылки и ту же проверку приватности. Отдельно включённые ссылки на плейлисты продолжают действовать. Подробнее: `21_account_privacy.md`.

Общие кнопки «Назад», ранее добавленные во все страницы через AppShell, удалены по просьбе пользователя. Внутренние элементы навигации чата и музыкальной библиотеки остаются.

Проверки: `node --test tests/*.test.mjs` — 52 теста, включая 5 проверок реальных коллекций, отсутствующих данных, смены аккаунта, чужого профиля и недоступных песен. `node tests/check-profile-music-db.mjs` проверяет повторное выполнение миграции, независимость видимости от ссылок, права владельца, выбор опубликованных песен, отсутствие личной истории/email/токенов и доступ к обложкам. Также выполнены TypeScript, ESLint, production-сборка и проверка интерфейса.
