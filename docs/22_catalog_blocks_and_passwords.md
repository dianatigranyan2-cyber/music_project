# Управление каталогом, блокировки, пароли и музыка в сообщениях

## Управление музыкой

Откройте профиль → Настройки → «Управление музыкальным каталогом» (`/admin/music`).
Доступ имеет только аккаунт UserZero_Diana. Право привязано к его UUID, а не к данным, которые пользователь может изменить в браузере.

1. Нажмите «Добавить трек».
2. Укажите название, исполнителя, альбом (необязательно), жанр, ссылку на источник, лицензию и текст указания автора.
3. Выберите MP3/M4A до 50 МБ и, при необходимости, JPG/PNG/WebP до 5 МБ.
4. Нажмите «Сохранить». Песня появляется в библиотеке без редактирования JSON и повторной сборки сайта.
5. «Изменить» позволяет исправить метаданные, заменить обложку или снять песню с публикации. Аудиозапись после добавления не заменяется; другая версия загружается отдельным треком.

Исполнители и альбомы создаются автоматически и повторно используются по имени. Поддержаны лицензии существующей библиотеки: CC BY 4.0 и CC BY-SA 3.0. Источник и условия видны в информации о песне.

Миграция `supabase/catalog_admin.sql` применена в проекте blwscmxpbvnbsoqzqssg. RLS защищает каталог и Storage. API проверяет авторизацию, роль, размер, сигнатуры файлов и метаданные. SHA-256 предотвращает повторное добавление одинакового аудио. Сохранение метаданных выполняется атомарно; после ошибки новые файлы удаляются. Старые обложки сохраняются, чтобы не ломать ранее открытые ссылки.
Файлы `music-audio` и `music-covers` открыты для чтения: снятие с публикации убирает песню из каталога, но не является способом сделать ранее опубликованный файл конфиденциальным.

## Блокировки

Кнопка доступна в чужом профиле, в верхнем меню «⋯» чата и в меню друга. Меню раскрываются в пределах экрана, подтверждение блокировки открывается отдельным диалогом. Перед блокировкой показывается подтверждение с последствиями. Список для разблокировки находится в настройках.

Блокировка действует в обе стороны: нельзя отправить сообщение, запрос дружбы или присоединиться к прослушиванию. Удаляется существующая дружба/заявка и текущая связь совместного прослушивания. История сообщений и отметки прочтения остаются доступными. Разблокировка не восстанавливает дружбу автоматически; чужую блокировку снять нельзя.

Миграция `supabase/user_blocks.sql` применена. Проверки работают также при прямых запросах к базе, включая обновление старой заявки и конкурирующее присоединение. Состояние интерфейса обновляется после действия, при фокусе и раз в 10 секунд. Прежние собеседники остаются в списке чатов, даже если перестали быть друзьями.

## Пароли и восстановление

Регистрация требует два совпадающих пароля. Кнопка глаза показывает и скрывает каждый пароль; аналогичная кнопка есть при входе и смене пароля. Допустимая длина: 6–72 символа.

«Забыли пароль?» на странице входа открывает `/forgot-password`. Письмо ведёт через `/auth/callback` к `/reset-password`: PKCE-код обменивается на сессию, затем пользователь сам вводит новый пароль два раза. Произвольная внешняя переадресация из callback запрещена. Просроченная ссылка предлагает запросить новую. Пароли не записываются в профиль, логи или сообщения. Письмо следует открывать в том же браузере, где оно было запрошено.

В Supabase добавлен точный разрешённый адрес:
`http://localhost:3000/auth/callback?next=/reset-password`.
Для опубликованного сайта нужно добавить такой же адрес с его реальным HTTPS-доменом.

**Остаётся подключить почтовый сервис.** Custom SMTP в проекте выключен. Встроенная почта Supabase предназначена для тестирования, отправляет только участникам команды проекта, с лимитом 2 письма в час. Доставка и смена реального пароля при проверках не выполнялись.

Для бесплатного старта выбран Brevo: план Free включает 300 писем в сутки и SMTP. Пользователь должен создать собственный аккаунт и подтвердить отправителя. При использовании Gmail без своего домена Brevo может заменять домен отправителя на `brevosend.com`; для постоянной эксплуатации лучше подтвердить свой домен.

Настройка после создания аккаунта:

1. В Brevo подтвердить адрес отправителя и доступность отправки транзакционных писем.
2. В разделе SMTP получить SMTP login и создать **SMTP key**, а не API key.
3. Supabase → Authentication → Emails → SMTP Settings → Enable custom SMTP.
4. Host: `smtp-relay.brevo.com`, Port: `587`, Username: SMTP login из Brevo, Password: SMTP key. Sender email: подтверждённый отправитель, Sender name: `Melo`.
5. Секретный ключ пользователь вводит непосредственно в Supabase; его не нужно добавлять в `NEXT_PUBLIC_*` или отправлять в чат.
6. Сохранить настройки и вручную проверить письмо и смену пароля на своём аккаунте. Общий лимит Supabase Auth действует отдельно от квоты Brevo.

Источники, проверенные 16 октября 2026:

- [Supabase SMTP restrictions](https://supabase.com/docs/guides/auth/auth-smtp)
- [Brevo Free plan](https://help.brevo.com/hc/en-us/articles/208589409-About-Brevo-s-pricing-plans)

## Музыка в чате

Откройте переписку → «⋯» в правом верхнем углу → «Отправить музыку» → найдите песню или выберите свой плейлист → «Отправить». У плейлиста должен быть заранее включён доступ по ссылке в «Моей музыке».

Получатель видит карточку с настоящими данными из каталога/подборки, обложкой и кнопкой воспроизведения. Плейлист можно открыть отдельно. Неопубликованная песня или отключённая ссылка отображаются как недоступные. Перед запуском плейлиста доступ по ссылке проверяется повторно. При прослушивании с ведущим самостоятельный запуск карточки отключён.

Карточки хранятся в `messages.content` как версионируемый строгий маркер `♫ Melo · Трек|Плейлист\nmelo:track|playlist:UUID`. В сообщении нет доверенных названий, обложек или внешних URL от отправителя: интерфейс разрешает UUID через существующие API каталога. Обычный текст, ответы на истории и старые сообщения продолжают работать.

## Исправление ошибок восстановления (16 октября 2026)

В журнале Supabase обнаружены две разные причины: `PUT /user` вернул 422, поскольку новый пароль совпадал с прежним; последующие `POST /recover` вернули 429 `email rate limit exceeded`. Первый переход по ссылке дошёл до операции смены пароля. Ошибки теперь показываются отдельно: повтор старого пароля, лимит писем, недоступный отправитель, истёкшая ссылка и проблема сети. Сырые серверные сообщения и секреты пользователю не выводятся.

Лимит почтового провайдера не отменяется кодом интерфейса. Пока не настроен собственный SMTP, требуется дождаться восстановления квоты встроенной почты Supabase. Повторные письма и реальные смены пароля агентом не выполнялись.
