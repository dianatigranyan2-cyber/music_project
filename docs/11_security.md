# 11. Безопасность

## 1. Защита данных (Row Level Security — RLS)
В приложении Melo клиент взаимодействует с базой данных напрямую через библиотеку `@supabase/supabase-js`. Безопасность полностью полагается на механизмы RLS PostgreSQL.

### Ключевые требования к политикам безопасности:
1. **`profiles`**:
   - `SELECT`: разрешено всем авторизованным пользователям (`TO authenticated`).
   - `UPDATE`: разрешено только владельцу записи (`auth.uid() = id`).
2. **`friend_requests`**:
   - `SELECT` и `UPDATE`: разрешено только участникам заявки (`auth.uid() = sender_id OR auth.uid() = receiver_id`).
   - `INSERT`: разрешено при условии `auth.uid() = sender_id`.
3. **`messages`**:
   - `SELECT`: только участникам диалога (`auth.uid() = sender_id OR auth.uid() = receiver_id`).
   - `INSERT`: только от своего имени (`auth.uid() = sender_id`).
   - `DELETE`: только автору сообщения (`auth.uid() = sender_id`).
   - `UPDATE`: защищено на уровне RPC-функции `edit_own_message`, проверяющей `auth.uid() = sender_id`.
4. **`stories`**:
   - `SELECT`: доступно авторизованным пользователям для активных историй (`expires_at > now()`).
   - `INSERT`: только от своего имени (`auth.uid() = user_id`).
   - `DELETE`: только владельцу истории (`auth.uid() = user_id`).

## 2. Безопасность Supabase Storage
- **Бакет `avatars` (Public)**:
  - Публичный доступ на чтение по прямой ссылке.
  - Ограничение записи: только авторизованные пользователи в свою папку `${user.id}/*`.
- **Бакет `stories` (Private)**:
  - Приватный доступ. Файлы недоступны по прямой ссылке без авторизации.
  - Доступ осуществляется исключительно через временные подписанные URL (`createSignedUrl`) со сроком жизни 300 секунд (5 минут).

## 3. Рекомендации по устранению потенциальных уязвимостей
1. **Серверные ограничения Storage**:
   - Сейчас проверка типов (MIME) и размера (до 5 МБ) файлов выполняется на клиенте в JavaScript. Рекомендуется настроить конфигурационные лимиты размера бакета и MIME-фильтры в консоли Supabase.
2. **Очистка Storage при удалении записей**:
   - Реализовать триггеры базы данных или pg_cron для автоматической очистки удаленных или просроченных файлов историй.
